Se programó el famoso juego del UNO siguiendo las reglas oficiales que contiene (emitiendo algunas que rara vez
se usan en la práctica), se hizo de forma gráfica (con el uso de imágenes y usando el lenguaje C#.
Actualmente el juego solo se juega de forma local de 4 jugadores, próximamente será implementado para ser jugado
en diferentes ordenadores y cada uno con su propia perspectiva.
El juego lleva un registro de jugadas, los jugadores que han participado y sus victorias o derrotas, todo eso
se sube a una base de datos de mySQL conectada mediante una API escrita en Python.

El juego consta de un modelo cliente-servidor con host-jugador, primero los 4 jugadores ejecutaran el juego pero solo uno creara una sala, los demás solo se tendrán que unir a su sala por algun nombre o contraseña dados por el primer jugador, el primer jugador será el host por lo que tendrá que mantener el estado oficial del juego, validar acciones, aplicar reglas, retransmitir el estado a los clientes y administrar la sala al finalizar la partida, mientras que los otros jugadores serán los clientes que solo capturaran las entradas del jugador, las enviará al host, el host las analizará y les mandará el estado de vuelta, y el cliente solo se encargará de mostrarlo, las principales ventajas de este modelo es que es muy simple de implementar, también que si en caso de hubiera errores en algún cliente solo lo afectarian a el y no a todos, el principal inconveniente es que todo recae en el host, si se desconecta o tiene mala conexión todos los jugadores cliente se verán afectados, los detalles más específicos de los protocolos de comunicaciones están en Protocolo.md pero básicamente . Cada mensaje es una línea de JSON en UTF-8, todos usan la misma clase Mensaje, donde el campo tipo indica qué campos se usan. Los campos null no se envían. Si el documento y el código (Protocolo.cs) se contradicen, gana el código.
